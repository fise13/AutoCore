# AutoCore — Полные идеи продукта (iOS + macOS)

## 1) Видение продукта

AutoCore — это единая система управления автобизнесом: склад моторов, бухгалтерия, документы, продажи и аналитика в одном потоке.

- `macOS` — центр операционного управления: массовое редактирование, быстрые таблицы, контроль данных, администрирование.
- `iOS` — мобильный контур: быстрое внесение операций, скан документов, контроль статусов, уведомления и виджеты.
- Главный принцип: **одно состояние данных на всех устройствах** с понятной синхронизацией и предсказуемым UX.

---

## 2) Целевая аудитория и сценарии

### Роли
- Владелец бизнеса
- Администратор
- Бухгалтер
- Сотрудник склада/сервиса
- Наблюдатель (`viewer`)

### Ключевые сценарии
- Принять мотор на склад, обновить статус, продать мотор.
- Добавить приход/расход, отредактировать или удалить операцию.
- Отсканировать накладную на iPhone, подтвердить, синхронизировать на Mac.
- Просмотреть оперативную сводку в iOS-виджете.
- Управлять брендами, категориями, “специфичными” папками/локациями.

---

## 3) Северная звезда и KPI

### North Star Metric
- Количество корректно завершённых бизнес-операций в день (склад + финансы + документы) без ручного исправления в конце дня.

### Основные KPI
- Время от скана документа до подтверждённой операции.
- Доля операций, созданных через AI-скан без критических правок.
- Время синхронизации iOS <-> macOS.
- Ошибки прав (`permission denied`) и конфликтов данных.
- DAU по платформам и ретеншн 7/30.

---

## 4) Информационная архитектура

### Общие домены данных
- Компании, участники и роли.
- Моторы, бренды, категории, локации (“специфичные”).
- Финансовые операции (`income`, `expense`, `sale`, `refund`, `transfer`).
- Документы (накладные, заказ-наряды), позиции документа.
- История изменений, источники записи, связь с пользователем.

### Принципы
- Компания (`companyId`) — обязательный изолятор данных в облаке.
- Локальная БД для производительности и офлайн-поведения.
- Cloud ID обязателен для надежных update/delete.

## 5) Продуктовые идеи для iOS

## 5.1 Главная/Операции
- Быстрые действия сверху: `+ Приход`, `- Расход`, `Скан`.
- Понятные фильтры и статусы синка.
- Унифицированные ошибки в виде баннеров (без “сырого” системного текста).

## 5.2 AI-скан документов
- Пайплайн: `Image -> AI extraction -> Preview -> Confirm`.
- Fallback: `Vision OCR -> AI text extraction`, если image AI не удался.
- Проценты качества:
  - AI confidence,
  - покрытие данных,
  - сходимость итогов.
- Ручное подтверждение, если confidence низкий или суммы не сходятся.
- Выбор типа документа:
  - `Заказ-наряд` (обычно доход/работы),
  - `Накладная` (товарный контур/склад).
- Для `Накладной`: сопоставление мотора по серийному номеру и отметка как проданного.

## 5.3 Виджеты и Live-индикаторы
- Виджеты:
  - общая денежная позиция,
  - расходы за день по категориям,
  - недельная динамика.
- Обновление через App Group + timeline reload.
- Дальше: Live Activity для активного сканирования и фонового статуса обработки.

## 5.4 UX-идеи мобильного ввода
- “One-thumb flow” для добавления операции за 10–20 секунд.
- Шаблоны частых расходов.
- Умная автоподстановка контрагентов и категорий.
- Быстрые действия из push/local notification.

## 6) Продуктовые идеи для macOS

## 6.1 Склад (Excel-режим)
- Плотная таблица с клавиатурной навигацией.
- Практически бесконечные строки без лагов (ленивая загрузка/рендер).
- Редактирование как “черновик” + явное сохранение (`Cmd+S`).
- Индикатор “Не сохранено” + диалог при выходе:
  - `Сохранить и выйти`,
  - `Отмена`,
  - `Закрыть без сохранения`.
- Автоудаление мотора, если вся строка очищена и сохранена.

## 6.2 Управление каталогом и локациями
- Двойной клик по бренду -> переименование.
- “Специфичные” папки как реальные локации моторов.
- Перенос между локациями через редактирование поля локации/листа.
- Массовые операции по выбранным строкам.

## 6.3 Бухгалтерия на Mac
- Надежное удаление/редактирование операций.
- Единые правила доступа, одинаковая логика с iOS.
- История изменений по операции (кто, когда, что поменял).

## 6.4 Onboarding/Tutorial
- Отдельный экран обучения для macOS.
- Пошаговые карточки по ключевым сценариям:
  - склад,
  - операции,
  - скан-процессы с iOS,
  - синхронизация.

## 7) Синхронизация и надежность данных

### Цели
- Точная двусторонняя синхронизация iOS/macOS.
- Безопасные операции update/delete даже для legacy записей.
- Предсказуемое поведение при офлайне.

### Идеи улучшений
- Единый `Sync Health` экран:
  - время последней успешной синхронизации,
  - очередь локальных изменений,
  - конфликты.
- Явная стратегия конфликтов:
  - “последняя правка” + журнал,
  - ручной merge для критичных сущностей.
- Диагностика прав в рантайме:
  - проверка `companyId`,
  - проверка роли,
  - понятная причина отказа.

---

## 8) Безопасность и доступы

- Firestore Rules: строгая изоляция по `companyId`.
- Запрет изменения `companyId` в существующих документах.
- Ролевые права на write/delete.
- Трассируемость: кто удалил/изменил документ.
- Хранение ключей API только через защищённый конфиг/секреты (без hardcode в проде).

---

## 9) UX/UI стандарты (обе платформы)

- Единый язык интерфейса (цвета, кнопки, баннеры, состояния).
- Скелетоны и мягкие анимации вместо “пустых” экранов.
- Всегда видимый статус состояния:
  - загрузка,
  - синхронизация,
  - ошибка,
  - успех.
- Дизайн ошибок:
  - человеческий текст,
  - действие “что сделать дальше”.

---

## 10) Технические идеи для масштабирования

- Разделить слой синка на:
  - ingestion,
  - merge,
  - conflict resolution.
- Вынести AI extraction в модуль с тестируемыми контрактами.
- Контрактные тесты для правил Firestore + критических CRUD флоу.
- Performance budget для больших таблиц и списков.
- Метрики в runtime: время скана, время сохранения, ошибки прав, частота конфликтов.

## 11) Предлагаемый roadmap

## Этап 1 — Стабильность (1–2 недели)
- Дожать виджеты и App Group на всех сборках.
- Закрыть остаточные permission edge cases.
- Укрепить удаление/редактирование операций на обеих платформах.

## Этап 2 — Продуктивность (2–3 недели)
- Полировка UX кнопок и быстрых действий.
- Шаблоны операций и автоподстановка.
- Улучшение сценариев для “специфичных” локаций моторов.

## Этап 3 — AI и документы (2–4 недели)
- Повысить качество AI extraction (prompt/versioning/telemetry).
- Live Activity для долгого скана/обработки.
- Расширение типов документов и валидаций.

## Этап 4 — Аналитика и контроль (2 недели)
- Dashboard качества данных.
- Экран “Sync Health”.
- KPI панель по эффективности бизнеса.

---

## 12) Идеи “вау” функций

- “Умный день бухгалтера”: список того, что сегодня не закрыто.
- AI-подсказки по аномалиям расходов.
- Предиктивный остаток по складу и предупреждение о дефиците.
- Голосовой ввод операции на iPhone.
- Быстрый экспорт отчётов в один клик.

---

## 13) Критерии качества перед релизом

- Нет пустых виджетов при корректной авторизации и наличии данных.
- Любая операция (create/update/delete) синхронно воспроизводима на iOS и macOS.
- Ошибки прав отображаются понятным сообщением и actionable-подсказкой.
- Скан-документ проходит путь до сохранения без “тупиков”.
- В таблицах macOS нет зависаний на больших объёмах.
